# Agent Orchestrator

Governed, agentic software-engineering automation: a prototype that turns a requirement into a reviewable
engineering outcome, with agents executing under explicit controls and humans owning approvals.

**Version: v0.5.4 (admin page with one-click service launch, real LLM support)**

## What this version contains
* **Orchestration engine** (`orchestrator/core`): explicit dependency graph with entry/exit gates, parallel branches
  with a join, stateful execution, bounded retries with exponential backoff, fallback agents, checkpoint and
  rollback of failed re-plans, safe-stop, human approval checkpoints, change-controlled re-planning, and
  **automatic re-planning**: a changed upstream output is fingerprinted and only the nodes that depend on it are
  redone (an identical change does nothing).
* **Governance** (`orchestrator/governance`): policy-as-code for security, compliance and change control (every
  block names its policy), a workflow linter that refuses to run a workflow missing mandatory controls, a
  sandbox that executes generated tests, a hash-chained audit log, and reliability metrics (success rate, retries,
  fallbacks, rollbacks, MTTR, latency).
* **Scenario 1, greenfield:** a URL shortener (standard library, SQLite, WSGI) built through the governed graph:
  code, 32 tests and docs, each passing its gates.
* **Web UI:** a single-page UI generated by its own pipeline node (`ui`) and served at `/` with a strict,
  hash-based Content-Security-Policy; 7 UI-specific security and compliance policies.
* **Planner:** requirements are decomposed into tasks mapped to workflow stages; policies check the plan is acyclic,
  executable in the order stated, and traces every acceptance criterion to real tests or gates.
* **Scenario 2, brownfield:** fixing a real data-integrity bug (BUG-142) in the existing service: grounded impact
  analysis, a patch bound to its declared blast radius, backward-compatible API, and a regression test that must
  fail on the old code.
* **`simple_graph/`:** a small LangGraph-style version of the same idea, useful for understanding the design.
* Agents are an **offline mock LLM** by default (reviewed reference artifacts, no API key needed; the gates judge real
  code either way). A **real model** can be put behind any or all agents (`--llm anthropic`), with feedback on retries,
  a hard call budget and token accounting; see `docs/real-llm.md`. Not yet exercised against the live API in the build
  environment.

* **Scenario 3, ambiguous:** "make links expire sensibly": the vague request becomes structured questions; high-risk
  ones can only be answered by a human (no human, no guess: the run stops safely); decisions are validated, must
  appear in the code, and can be changed later with an automatic, minimal, rollback-safe re-plan.

* **Admin page** (`python -m orchestrator.admin`): a local control panel to write a requirement, switch between mock and
  real agents, generate, watch the run and make every human decision (approvals, questions, stop, change an answer) on
  the page, then **start the generated service from the page** (loopback-only, scrubbed environment, confirmation for
  real-model code); see `docs/admin-page.md`.

**Planned for later versions:** architecture overview and final engineering summary.

## Setup (Python 3.10+)
```
python -m venv venv
venv\Scripts\activate            # Windows        (Linux/macOS: source venv/bin/activate)
pip install -r requirements-dev.txt
```

## Run the tests
```
python -m pytest -v
```
Expected: **no failures**. With Node.js 18+ and `langgraph` both installed that is 366 passed; without Node.js the 2 browser-script
tests are skipped, and without `langgraph` its 1 comparison test is skipped. Two tests are skipped automatically (reported as skipped, not failed) if an optional
tool is missing: the LangGraph comparison needs `pip install langgraph`, and the real-browser-logic UI test needs
Node.js 18+ on PATH. Each of the shortener's own tests is listed by name in `tests/test_shortener_service.py`.

## Try it
```
python -m orchestrator.cli run shortener --approve auto                       # build the URL shortener
python runs/<run-id>/artifacts/implementation.py 8000                          # run the generated service
python scripts/smoke_test.py                                                   # 25 checks against the running server
python scripts/run_shortener_tests.py                                          # list the shortener's own tests
```
Then open **http://localhost:8000/** for the web UI (it is `ui.html`, produced by the pipeline and served from the
same folder as `implementation.py`).

Admin page (everything below, but with buttons; see `docs/admin-page.md`):
```
python -m orchestrator.admin --open        # http://127.0.0.1:8765/  (local only)
```

Real model and your own requirements (see `docs/real-llm.md`):
```
set ANTHROPIC_API_KEY=sk-ant-...                      # Windows Command Prompt; PowerShell: $env:ANTHROPIC_API_KEY="..."
python -m orchestrator.cli run shortener --approve auto --record llm-records/preview            # free preview of every prompt
python -m orchestrator.cli run slugify --llm anthropic --approve auto                           # smallest live test (~6 calls)
python -m orchestrator.cli run shortener --llm anthropic --llm-roles architect,doc_writer,reviewer --approve auto   # hybrid
python -m orchestrator.cli run shortener --llm anthropic --requirement-file examples/requirements/url-shortener.md --approve auto
```
Edit `examples/requirements/url-shortener.md` to rewrite the requirements in your own words. With the default mock, a
custom requirement is ignored (the CLI says so): your wording only matters with a real model.

Ambiguous scenario (see `docs/scenarios/03-ambiguous-expiry.md`):
```
python -m orchestrator.cli run ambiguous --approve auto                                   # nobody answers: stops safely
python -m orchestrator.cli run ambiguous --approve auto --answer default_ttl_days=90      # a human answers the high-risk question
python -m orchestrator.cli run ambiguous --approve ask                                    # you are asked in the terminal
python -m orchestrator.cli run ambiguous --approve auto --answer default_ttl_days=90 --revise-answer default_ttl_days=180
                                                          # automatic re-plan: only the 6 dependent nodes are redone
python -m orchestrator.cli run ambiguous --approve auto --answer default_ttl_days=90 --revise-answer default_ttl_days=90
                                                          # same answer: nothing happens
python -m orchestrator.cli run ambiguous --approve auto --answer default_ttl_days=90 --revise-answer default_ttl_days=180 --break-on-revise
                                                          # re-run fails: the change AND the new answer are rolled back
```
Exit codes: 0 completed, 1 halted, 2 workflow rejected by the governance lint, 3 a requested revision was refused.

Brownfield scenario (fix BUG-142 in the existing service; see `docs/scenarios/02-brownfield-orphaned-clicks.md`):
```
python -m orchestrator.cli run brownfield --approve auto
python scripts/run_shortener_tests.py baseline     # the buggy code passes its own 31 old tests
python scripts/run_shortener_tests.py fixed        # 34 pass, including the 3 regression tests
python -m orchestrator.cli run brownfield --approve auto --violate scope-creep   # also: api-break, ungrounded-impact,
                                                                                 # no-regression-test, drop-tests, changelog-no-ticket
python -m orchestrator.cli run shortener --approve auto --violate ui-innerhtml   # also: ui-cdn, ui-unlabelled
```
Governance and resilience demos (use `slugify` for the toy workflow or `shortener` for the real one):
```
python -m orchestrator.cli run shortener --approve auto --violate secret        # policy blocks a leaked key, agent retried
python -m orchestrator.cli run shortener --approve auto --violate plan-cycle    # planner's cyclic plan is blocked
python -m orchestrator.cli run shortener --approve auto --violate import        # unapproved dependency blocked
python -m orchestrator.cli run shortener --approve auto --violate thin-tests    # compliance policy halts the run
python -m orchestrator.cli run shortener --approve auto --fail developer:5      # retries exhausted -> fallback agent
python -m orchestrator.cli run shortener --approve auto --revise-design ok      # design change -> re-plan, downstream redone
python -m orchestrator.cli run shortener --approve auto --revise-design fail    # re-run breaks -> change rolled back
python -m orchestrator.cli run shortener --approve deny:release                 # human refuses the release -> safe-stop
python -m orchestrator.cli run shortener                                        # interactive approvals
```
Every run writes `runs/<id>/{audit.jsonl, metrics.json, report.md, artifacts/}`; the report includes a governance
timeline of retries, fallbacks, re-plans, rollbacks and approvals.

Simple graph version: `python -m simple_graph.demo happy` (also `fix_loop`, `always_bad`, `reject_once`,
`--engine langgraph`, `--ask`).

## Layout
```
orchestrator/   engine, governance (policies, gates, sandbox), observability, workflows, LLM clients, admin page
simple_graph/   small LangGraph-style version
tests/          unit, scenario, end-to-end and web-UI tests
scripts/        smoke test for a running server, helpers
examples/       plain-English requirement templates
docs/           testing approach, policy catalog, decisions (ADRs), scenario write-up, AI usage log
```
